- **日期**：2026-10-25

- **窗口**：`2016-01-29..2023-12-29`（调优窗口；holdout `2024-01-01..2026-10-20` 未查询）

## 1. 一句话结论

**不换 RULE。** LightGBM 的漂亮数字是内样本拟合，注册表里同一个工件自己的 `deployment_note`
记录了它在真 holdout 上三配置全输；LSTM 是本轮唯一可裁决的 ML 臂，它按预登记判据**未通过**。
没有任何 `ETF_*` `ModelVersion` 被激活。

---

## 2. 方法与口径

| 项 | 取值 |
| :--- | :--- |
| 切分 | 6 个连续块，每折 hold out 2 块 → C(6,2)=15 个切分，6 个互不相同的块 |
| purge | 1 session（label horizon） |
| embargo | 5 sessions（每个 held-out 块之后） |
| 审计 | `audit_combinatorial_folds` 全部 15 个切分通过 |
| 度量方式 | 每臂跑**一条连续曲线**，按块切片；块内 maxDD 以自己的起点为峰 |
| 块基数 | 每块收益以块前最后一个净值点为基，所以块首日的收益不被丢掉 |
| 持仓规则 | 四臂逐字段相同：`BIWEEKLY / mom120 / 绝对动量关 / equal / dedup on / cap 2 / max_swaps 2`；只有 p5 臂改 `max_positions` |

**这不是逐折重训的 CV。** 每个块用的是**同一个已训练好的工件**，所以"样本外"只对
*参数选择*成立，对*模型拟合*不成立——这正是第 3 节判定有效性的原因。

| RULE p5 | 无（规则） | — | 同上 | **有效** |
| LightGBM | `etf-lgb-20d-lambdarank-2023-11-30-oos23`（id 63） | 2023-11-30 | 块 1–5 全部内样本，块 6 仅最后一个月外 | **不可裁决** |

**这是一个"带内样本优势仍然输"的读数，所以它的失败比失败本身更有力。**

## 5. 预登记判据与裁决

判据在跑之前写死（见 spec `ETF_Rotation_Gap_Closure_task-017.md` 的 R1–R4），跑完不改。

### R1 — row 256 稳定性：只陈述，不判定
六块中位 Sharpe 0.1620，83.33% 为正，块 5 为负。**结论：参考配置在时间上高度不均匀**，
不据此改任何默认值。

### R2 — p3 vs p5：三项全胜才改默认
判据依次为 Sharpe 中位数 → 正收益块占比 → maxDD 中位数。

| 判据 | p3 | p5 | 胜方 |
| :--- | ---: | ---: | :--- |
| Sharpe 中位数 | 0.1620 | 0.2725 | p5 |
| 正收益块占比 | 83.33% | 66.67% | **p3** |
| maxDD 中位数 | 17.96% | 14.54% | p5 |

**裁决：默认值保持 3。** p5 未三项全胜。这条记录的价值不在"p3 更好"，而在
"更高的中位 Sharpe 是用一致性换来的"——只看中位数会把 p5 误读成升级。

### R3 — ML vs RULE：三项全满足才算 CV leg通过
判据：ML 的 Sharpe 中位数高于 RULE，**且**正收益块占比不低于 RULE，**且** maxDD 中位数
不高于 RULE + 2pp。

| 臂 | Sharpe 中位 | 正收益块 | maxDD 中位 | 判据结果 |
| :--- | ---: | ---: | ---: | :--- |
| RULE | 0.1620 | 83.33% | 17.96% | 基准 |
| LSTM | 0.1238 | 66.67% | 15.93% | Sharpe 负、一致性负、回撤胜 → **未通过** |
| LightGBM | 2.4839 | 100% | 7.56% | 全部内样本 → **不可裁决** |

**裁决：CV leg未通过。** 完整闸门还需要 10b 的前向证据（影子账本 ≥20 次调仓，需数月），
本轮不可能满足；因此即使 CV leg通过也不会激活，何况它没有通过。

## 6. 与注册表 holdout 记录的交叉印证（关键）

本轮的 CPCV 是在**已烧掉的 holdout 之外**做的第二次独立测量。把它和注册表里 ML 工件
自己的 `deployment_note`（当年在真 holdout 上跑出来的）并排看，结论一致：

| 工件 | holdout（2024-01-01..2026-10-20）实测 | 闸门 |
| :--- | :--- | :--- |
| LightGBM id 63（本轮钉住的就是它） | alpha **−0.0141 / −0.0026 / +0.0338** vs RULE **+0.1821 / +0.1757 / +0.1752**；holdout rank IC 仅 4/6 折为正，均值 0.0306 | 三配置**全败** |
| LSTM id 64（`2023-11-30-oos23`，非本轮钉住的 id 100） | alpha +0.1646 vs RULE +0.1821（#1 配置）；另两配置胜，但 beta 1.08–1.19 vs RULE 0.61–0.69、maxDD 0.41–0.42 vs 0.18–0.20 | 2/3 通过但不干净 → 不上线 |
| LSTM id 100（本轮钉住，Phase D row 209） | alpha 0.0888 vs 0.1821、maxDD 0.4567 vs 0.2000、beta 1.1038 vs 0.6070 | **FAIL** |
| ENSEMBLE id 65 | alpha +0.0641 / +0.0712 / +0.0355 vs RULE +0.1821 / +0.1757 / +0.1752 | 三配置**全败** |

**同一个 LightGBM 工件，在训练集内 Sharpe 2.48，在真 holdout 上 alpha −0.014。** 这两行数字
放在一起，就是"内样本分布不能当能力"的最直接证明，也是不能拿它替换 RULE 的理由。

### 6.1 顺带查出的一个缺陷（已修）

`rotation_engine._call_predictor` 原先只把 `['ts_code', *features]` 交给 predictor，丢掉了 `date`。
LSTM 的评分契约需要每行的 as-of 日期；缺了它会退回"最新 eligible 快照"，于是
**每一个历史 session 都拿到同一份分数向量**——整段回测实际上持有一个静态组合。
这解释了 Phase D row 209 的 beta 1.10 与 maxDD 0.46：那不是模型的风险特征，是"两年半不换仓"
的产物。

修复后 `date` 随帧传递（LightGBM 按训练列 reindex，数值逐位不变），本轮 LSTM 运行
**0 条** "no date column" 告警。**因此 row 209 的 LSTM 数字不应再被引用**；用修复后的代码
重测需要再查一次已关闭的 holdout，纪律不允许，故只记录失效、不补新数字。

1. **RULE 保持生产。** 不激活任何 `ETF_*` `ModelVersion`（active 集合仍为空）。
2. **`max_positions` 默认保持 3**（R2 裁决）。
3. **LightGBM 的 CPCV 分布只作上限记录**，不进入任何对比榜单、不作为决策依据。
4. **Phase D 的 LSTM 存量数字标记为失效**（§6.1）。

## 10. 边界与免责

- 六个块**不是独立样本**：它们是同一条连续曲线的切片，资金路径相连。分布读作"分段稳健性"，
  不是"六次独立试验"。

- **IC ≠ alpha**：IC 与组合指标分开列示，不混排、不单独据 IC 宣称优劣。

## 11. 按折重训复赛（2026-10-25 晚，Phase 14-15）

§3-§6 的四臂读数有一个共同的弱点：ML 臂用的是**已训练工件**，其训练窗口覆盖被测块。本节改用 Phase 14 的按折重训：每个块由一个**从未见过该块**的模型评分。

### 11.1 方法

- 面板 `2016-01-29..2023-12-31`，6 块，`--cpcv-test-blocks 1`（每块恰好一个模型），窗口与 §4 可比。
- `run_etf_rotation_backtest --cpcv-retrain`：对每块用"其余块 + purge + embargo"训练一个折模型，只给该块打分与跑组合回测，然后丢弃——不注册、不落盘、不激活。
- **每块是独立运行、从初始资本起算**：一个块的模型只对该块有效，没有可切片的连续曲线。因此 RULE 基准也用同一模式重跑，否则比较会混用两种方法。
- 泄漏断言：任何训练日期落在自己块内即拒绝训练。

| 臂 | Sharpe 中位数 | 正收益块 | maxDD 中位数 | 区间收益中位数 | 块内 rank IC 中位数 |

### 11.3 裁决（对照 §5 预登记的 R3'）

R3' 要求三条同时成立：Sharpe 中位数 > RULE、正收益块占比 ≥ RULE、maxDD 中位数 ≤ RULE + 2pp。

| 臂 | Sharpe | 一致性 | 回撤 | 结论 |
| :--- | :--- | :--- | :--- | :--- |
| LightGBM | 输（−0.0136 < 0.2227） | 输（50% < 83.33%） | **赢**（9.35% < 19.97%） | 不通过 |
| LSTM | 输（0.0249 < 0.2227） | 输（66.67% < 83.33%） | 赢（17.32% < 19.97%） | 不通过 |

**结论：不替换 RULE。** 两条 ML 臂在收益与一致性上都不敌 RULE，只在回撤上占优。这与 §6 的观察一致，也是本轮最诚实的一句话：**ML 的价值不在选股，在降低回撤**。§6 里 LSTM 六块 IC 全正而组合输给 RULE，原因现在更清楚——正的 rank IC 不足以抵消换手与选股集中度带来的收益损失。

**§3-§6 的 LightGBM 读数（Sharpe 中位数 2.4839）作废**：按折重训后是 −0.0136。两者差 2.5 个 Sharpe，就是"用见过答案的模型评分"的代价。

### 11.4 一个方法学发现：序列模型的 purge 必须覆盖窗口长度

首次 LSTM 重训被护栏拦下两次，两次都是真问题：

1. `--cpcv-embargo 5` 时，块后有 15 个训练日期的 20 日输入窗口会伸进块内 → "14 holdout dates appear inside training windows"。
2. 修正后仍触发"a training target date is not before the holdout start"——该断言原本只对 expanding 折成立，组合折合法地保留块后日期。

**规则**：对序列模型，embargo 必须 ≥ `sequence_length`。LightGBM 是逐行特征，`embargo=5` 足够；LSTM 用 `--cpcv-embargo 20`。这不是可调偏好，是有效性前提——不足时模型的输入里就有块内行情。表 11.2 的 LSTM 臂即用 20 跑出。

### 11.5 第四臂：RULE 选股 + LightGBM 否决（已测）

**假设**：ML 分数当**过滤器**有用，当**选择器**没用。§11.3 的两条臂都是"用 ML 排序"，输在收益与一致性、赢在回撤——这正是过滤器该有的形状。

**实现**：`--cpcv-retrain --cpcv-hybrid --model LIGHTGBM`。每块训练一个折模型（同 11.1），但**引擎的选择模型仍是 RULE**；折模型只把横截面里 ML 分数处于末位 20% 分位的候选剔除，再走 RULE 的选择约束。分位**固定 20%，全程不调**。

| 1 | 2016-01-29..2017-05-26 | 0.6654 | 0.8032 |
| 2 | 2017-05-31..2018-09-13 | 0.1688 | 0.2906 |
| 3 | 2018-09-14..2020-01-10 | 0.7487 | 0.9109 |
| 4 | 2020-01-13..2021-05-13 | 1.2287 | 1.3841 |
| 5 | 2021-05-14..2022-09-02 | −0.1436 | 0.0463 |
| 6 | 2022-09-05..2023-12-28 | 0.2227 | −0.3911 |

| 臂 | Sharpe 中位数 | 正收益块 | maxDD 中位数 | 区间收益中位数 | 最差块 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| RULE | 0.2227 | 83.33% | 17.97% | +3.03% | +3.03%（第 5 块 −7.76%） |
| **RULE + LGB 否决** | **0.2906** | **83.33%** | **15.62%** | **+3.27%** | **−8.78%** |

**结论：LightGBM 否决臂是唯一在三项 leg（criteria，与持仓 leg 同词、由上下文区分）上都不劣于 RULE 的 ML 臂。** 按预登记的新臂判据（"三项 leg中至少两条不劣、且 maxDD 不更差，即可进入前向对照"），它**通过**——Sharpe 与 maxDD 都更好，一致性持平。**但 §11.6 用 LSTM 换掉否决模型后结论反转**，所以这条通过不能单独作为证据。

**但必须同时说清两点**：

1. **尾部更差**。第 6 块 −8.78%，RULE 是 +3.03%。中位数改善是"少输在中间块"，不是"更抗尾部"。
2. **一个分位、一个配置、6 块**。这是稳定性读数，不是显著性检验；分位一旦开始调就又是一次搜索，本轮不动。

因此本轮的正确结论不是"换成混合臂"，而是**"RULE 保持生产，混合臂获得进入前向对照的资格"**。前向窗口（2026-10-25 起、≥20 次调仓）是它下一道门。

### 11.6 第四臂的对照：LSTM 否决（已测）

同一套 `--cpcv-hybrid`，把否决模型换成 LSTM（`--cpcv-embargo 20`，见 §11.4）：

| 臂 | Sharpe 中位数 | 正收益块 | maxDD 中位数 | 区间收益中位数 | 最差块 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| RULE | 0.2227 | 83.33% | 17.97% | +3.03% | −7.76% |
| RULE + LGB 否决 | **0.2906** | 83.33% | **15.62%** | **+3.27%** | −8.78% |
| RULE + LSTM 否决 | 0.1515 | 83.33% | 17.99% | +1.37% | −22.61% |

**LSTM 否决不通过**：Sharpe 中位数低于 RULE（0.1515 < 0.2227），回撤持平，最差块 −22.61% 远差于 RULE 的 −7.76%。

**这改变了 §11.5 的读法。** 两个否决模型的结论相反，所以"ML 当过滤器有用"**不是**一个稳健发现，而是**LightGBM 特有的**一个观测。正确的表述是：

- LightGBM 否决臂通过了预登记的 CV 判据（Sharpe 与 maxDD 都更好、一致性持平）；
- LSTM 否决臂不通过；
- 因此"过滤器"假设**未获独立复现**。一个配置、一个分位、6 块、两个模型给出两种答案——这不足以支撑任何生产变更。

**结论不变且更强：RULE 保持生产。** 混合臂连"进入前向对照"的资格都只能算 50%：LGB 版本可作为候选观察，但在前向窗口累积 ≥20 次调仓前，不该有别的动作。若要让这个假设变得可判定，下一轮的正确做法是**固定分位、只换否决模型与面板起点**做敏感性检验，而不是继续在同一个 6 块上换参数。

### 11.7 边界

- 每块独立起算，与 §4 的连续曲线分布**不可直接比较**；同一张表内只比同方法读数。
- RULE/LightGBM 臂 `embargo=5`、LSTM 臂 `embargo=20`；块边界相同，训练集不同。
- 6 块、单一面板；这是稳定性读数，不是显著性检验。
- 面板止于 2023-12-31，**未使用释放后的 2024-2026**（那会改变块边界，使本节与 §4 无法对照）。释放后的读数属下一轮，且只能叫调优数字。
