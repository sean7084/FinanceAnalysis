The root composes three runtime surfaces — a Django+DRF REST/ASGI server (manage.py → config.settings), a React/Vite frontend proxying /api and /ws to port 8000, and Celery Beat plus separate worker processes for ops/backtest/train-lightgbm/train-lstm queues — all launched via docker-compose.yml which builds each service from compose/local/django/Dockerfile with shared .env. The ten Django apps in the config child follow a strict upstream→derived ordering (markets → analytics/factors/macro/sentiment → prediction → backtest) enforced by app registry rather than imports, and every cross-sectional calculation, training filter, and daily prediction must honor the CSI 300/A500 membership cutoff defined in apps/markets/benchmarking.py. Shared infrastructure across children: PostgreSQL as primary store, Redis as cache/Celery broker/Channels layer, requirements/base.txt pinned per environment, and generated documentation facts produced by `python manage.py export_documentation_facts` against the live DB.
