The `config` package is a standard Django project root. Settings are layered: `settings/base.py` holds shared defaults (installed apps, middleware, database via `django-environ`, Redis cache/channel layers, DRF/SimpleJWT/drf-spectacular config, Celery broker/queues/schedules, email, alerting flags) and is imported wholesale by environment-specific modules `settings/local.py` (DEBUG=True, console email backend, permissive ALLOWED_HOSTS) and `settings/production.py` (placeholder for production overrides). The top-level `__init__.py` imports `celery_app` so Celery tasks are registered on Django startup. `urls.py` centralizes all HTTP routes under `/api/v1/` using a single `DefaultRouter` that registers viewsets from every `apps.*` module plus explicit paths for auth, admin, and drf-spectacular docs. `asgi.py` exposes an ASGI application combining the WSGI app with a Channels `ProtocolTypeRouter` that delegates WebSocket handling to `apps.analytics.routing.websocket_urlpatterns`; `wsgi.py` provides the standard WSGI callable; `celery.py` creates the Celery app, loads settings via the `CELERY_` namespace autodiscovery, and discovers task modules across installed apps. Dependency direction is one-way: this package depends on `apps.*` but nothing in `apps` depends back on `config` beyond importing settings.
