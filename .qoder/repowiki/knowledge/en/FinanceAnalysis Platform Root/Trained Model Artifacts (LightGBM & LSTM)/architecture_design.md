Flat artifact store organized by algorithm under `models/lightgbm` and `models/lstm`, with each subdirectory representing a single trained version identified by a date-stamped name (e.g. `30d_lgb-30d-2024-12-31`, `lstm-2024-12-31`). LightGBM versions bundle four pickled objects — `model.pkl`, `scaler.pkl`, `calibrator.pkl`, and `metadata.json` — per horizon variant, where metadata records feature names, LightGBM hyperparameters (`lgb_params`), pruning configuration, and training window. LSTM versions group three horizon-specific PyTorch weight files (`{horizon}d_model.pt`) alongside per-horizon metrics JSONs and a top-level `summary.json` that enumerates horizons, sequence length, per-horizon accuracy/status, and artifact paths. There is no runtime code in this scope; consumers load artifacts by resolving the desired version directory and deserializing the corresponding files.
